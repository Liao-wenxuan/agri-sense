## 1. 项目概述

### 1.1 背景

随着设施农业（温室大棚、连栋大棚、智慧农场）规模化发展，传统人工巡检与经验调控模式成本高、响应慢、易漏判。本项目面向中小型温室大棚与家庭农场，研发一套**轻量、低成本、易部署**的环境监测与智能调控软件平台。

### 1.2 项目目标

- 7×24 小时自动采集温室内的**温度、湿度、光照、CO₂、土壤湿度**等关键环境指标
- 当指标超出作物适宜区间时，**自动告警并触发联动控制**（通风、加湿、补光、灌溉等）
- 提供**实时数据可视化、历史回溯、告警管理、设备全生命周期管理**等核心能力
- 可基于历史数据训练轻量预测算法，**提前预判异常并优化调控策略**（加分项）

### 1.3 项目范围

- **包含**：纯软件系统；使用模拟设备或公开数据集；本地化部署
- **不包含**：硬件实物制作、定制 PCB、移动端原生 APP（响应式 Web 即可）、支付/物流等无关业务

## 3. 功能需求（按赛题 5 项要求逐条映射）

### FR-1 设备管理 — 对应赛题系统功能 ①

| 子项 | 说明 |
|---|---|
| 设备注册 | 新增设备，字段：设备ID、名称、类型、安装位置、传感器列表、控制能力 |
| 在线监测 | WebSocket 实时显示设备在线/离线状态、最后心跳时间、累计运行时长 |
| 远程控制 | 开关控制（通风扇、补光灯、加湿器、灌溉阀等）、参数调节（目标温度阈值等） |
| 故障记录 | 设备离线 / 传感器异常 / 控制指令失败 → 自动生成故障工单，支持溯源（时间、原因、处理结果） |

### FR-2 数据采集与展示 — 对应赛题 ②

| 子项 | 说明 |
|---|---|
| 实时采集 | 多设备多传感器并行上报，频率 1s~10s 可配 |
| 数据清洗 | 异常值剔除（3σ / 范围 / 缺失填充）、单位统一、时间戳对齐 |
| 实时展示 | 大屏式实时折线图（多指标多设备）、当前数值卡片、设备地图 |
| 历史查询 | 时间范围、设备、指标多维筛选，秒级响应 |
| 数据导出 | CSV / Excel，含完整元数据（设备、传感器、时间） |

### FR-3 告警管理 — 对应赛题 ③

| 子项 | 说明 |
|---|---|
| 告警规则 | 用户自定义阈值（如温度 > 30℃）、时间段、生效设备 |
| 告警触发 | 设备离线、指标超阈值、算法检测异常 |
| 告警渠道 | **站内信（WebSocket 弹窗）+ 邮件** 至少 2 种，可选扩展短信 |
| 告警记录 | 触发时间、设备、指标、当前值、阈值、处理人、状态（待处理/已处理/已忽略） |
| 告警处理 | 一键确认、派单、批量处理 |

### FR-4 智能算法 — 加分项 ④⑤

| 算法 | 用途 | 可视化 |
|---|---|---|
| 温度异常检测（Z-Score） | 提前发现缓慢漂移与突变 | 异常点高亮折线图 |
| 阈值自动寻优（可选） | 根据作物生长阶段调整告警阈值 | 阈值变化曲线 |
| 设备联动策略（规则引擎） | 告警触发后自动下发控制指令 | 联动链路时序图 |
| 温度预测（可选，LSTM/Prophet） | 预测未来 1h 温度趋势 | 真实值 vs 预测值曲线 |

> **算法必须与业务流程绑定**（如"温度异常 → 自动开启通风"），不可孤立运行。

### FR-5 系统管理

| 子项 | 说明 |
|---|---|
| 用户管理 | 登录/注册/角色（复用已有真注册真登录经验） |
| 农场/大棚管理 | 农场 → 大棚 → 设备 三级层级 |
| 系统配置 | 阈值模板、单位、数据采集频率 |

## 5. 数据需求

### 5.1 数据源（**首选公开数据集，省造数据时间**）

- Kaggle：`Smart Agriculture Dataset`、`Greenhouse Environment Monitoring`
- UCI：可改装为设备能耗时序的公开数据集
- 国家气象科学数据中心：历史气象（温度/湿度/光照）

### 5.2 备选模拟生成器（Node.js 脚本）

- **温度**：按昼夜正弦变化 15-35℃ + 随机扰动 N(0, 0.5)
- **湿度**：与温度负相关 40-80% + 扰动
- **光照**：按日出日落曲线 0-1000 lux
- **CO₂**：400-1500 ppm
- **土壤湿度**：缓慢变化 30-70%
- **故障注入**：随机让设备掉线 / 数据点异常（方便演示告警）

### 5.3 数据存储

- SQLite 三张核心表：`sensor_data`、`alerts`、`control_logs`（详见架构图）
- 历史数据保留 ≥ 90 天，按日分区（旧数据可导出后归档）
